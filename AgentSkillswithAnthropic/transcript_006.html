你可以將技能與工具、MCP 和子代理結合，建立強大的代理工作流程。讓我們逐一了解每個組件，看看它們如何協同運作，並學習何時使用什麼。

在這一課中，我們將探討技能如何融入代理生態系統。面對 MCP、技能、工具和子代理等眾多技術，讓我們確保了解它們如何協同工作。

在現有的應用程式中，我們可以引入 MCP 伺服器獲取所需的上下文，利用子代理進行獨立執行緒和平行化，並引入技能來處理可重複的工作流程。

Skills vs MCP（技能 vs 模型上下文協定）：模型上下文協定（Model Context Protocol）將我們的代理或 AI 應用程式與外部系統和資料連接。可能是外部資料庫、Google Drive 的資料等。任何時候你需要模型不知道的外部資料和上下文，MCP 都非常有用。

技能可以利用 MCP 提供的工具和資料來教導代理如何處理該資料。把 MCP 想像成提供所有底層工具，而技能是將這些工具組合成可重複產生所需資料的特定工作流程的指示集。

Skills vs Tools（技能 vs 工具）：工具是更底層的。想像你有錘子、鋸子和釘子（工具），而技能就像是「如何建造書架」的知識。

工具是存取系統的底層方式，提供代理完成任務所需的能力。事實上，工具被用於生成技能、讀取技能，甚至提供執行程式碼和載入技能的檔案系統。

技能以專業知識擴展能力，引入需要執行的額外檔案和腳本，但執行這些底層腳本和載入檔案的能力由工具提供。工具定義始終存在於上下文窗口中，而技能在需要時才漸進式載入。

技能允許我們建立可預測的工作流程，如果有工具不需要在每次對話中使用，可以透過技能和漸進式揭露在需要時才使用。

Subagents（子代理）：主代理可以建立子代理，子代理向父代理回報。子代理提供隔離的上下文、細粒度的權限，以及平行執行任務的能力。

主代理作為協調器可以利用所需的技能，子代理也可以使用特定技能。例如，一個 Code Reviewer 子代理可以利用指定你的團隊如何進行程式碼審查的技能。

整合範例 - Customer Insight Analyzer：主代理有一組工具（來自 MCP 伺服器），可以派遣子代理平行分析客戶訪談或調查。技能提供如何分析洞察、分類回饋、摘要發現的方法，確保以可預測的方式進行。

總結：

  • Prompts（提示詞）：對話中最基本的原子單位
  • Skills（技能）：將提示詞、對話、程式碼和資源打包在一起
  • Subagents（子代理）：可使用技能，在隔離的上下文中執行
  • MCP：提供子代理和主代理所需的工具

將上下文窗口視為公共財：用子代理減少主上下文窗口的負擔，用 MCP 載入必要資料，用技能漸進式載入。技能用於程序化、可預測的工作流程；子代理用於需要完整代理邏輯的專門任務。
