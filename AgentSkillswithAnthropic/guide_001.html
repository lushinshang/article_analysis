核心概念：什麼是 Agent Skills？為什麼重要？

Agent Skills 是一種輕量級的開放標準格式，用來擴展 AI 代理的能力。一個 Skill 本質上就是一個資料夾，裡面包含指令（instructions）、腳本（scripts）和資源（assets），讓代理能夠發現並執行特定任務。

一句話理解 Skills

如果你發現自己在不同對話中反覆輸入相同的 prompt，那就應該把它封裝成一個 Skill。

Skills 的核心結構

  • SKILL.md（必要）：包含技能名稱、描述和主要指令
  • 參考檔案（選用）：額外的 Markdown、腳本、範本、圖片等

Progressive Disclosure（漸進式揭露）

這是 Skills 設計中最關鍵的概念之一：

載入時機載入內容
永遠載入Skill 的名稱與描述（YAML frontmatter）
使用者請求匹配時SKILL.md 主體指令
視需要參考檔案、腳本、資源

業界觀點

Progressive Disclosure 的設計理念與資安領域的「最小權限原則」（Principle of Least Privilege）異曲同工——只在需要時才載入必要的上下文，避免 context window 被不必要的資訊污染。

學習路徑：本課程如何安排？

本課程按照由淺入深的順序，帶你走過 Skills 的完整生命週期：

  1. Claude.ai 實作：建立行銷分析 Skill，結合內建 Excel / PowerPoint Skills
  2. Claude API：用 Code Execution Tool + Files API 程式化地使用 Skills
  3. Claude Code：在 CLI 環境中安裝和使用 Skills，進行程式碼審查與測試
  4. Claude Agent SDK：建構研究代理，用 Skill 引導子代理協作

先備知識

你不需要付費訂閱。Skills 在 Claude.ai 免費方案中已可使用（搭配 Sonnet 4.5 或 Haiku 4.5）。

實務應用：Skills 在業界能做什麼？

典型應用場景

  • 重複性工作流封裝：每週行銷報告分析、客戶電話準備流程、季度業務回顧
  • 領域專業知識傳遞：品牌視覺規範、法律審查流程、資料分析方法論
  • 新能力擴展：產生簡報、生成 Excel 報表、建構 MCP 伺服器

跨平台可攜性

Skills 是開放標準，同一份 Skill 可以在以下環境使用：

  • Claude.ai / Claude Desktop
  • Claude Code
  • Claude Agent SDK
  • Claude API
  • Codex、Gemini CLI、Open Code 等第三方工具

常見誤區

誤區 1：把 Skills 當成「大型 Prompt」

Skills 不只是把 prompt 存成檔案。它的價值在於 Progressive Disclosure——只在需要時載入，保護 context window。如果你把所有資訊一次塞進 SKILL.md，就失去了這個優勢。

誤區 2：忽略 Skill 描述的重要性

名稱和描述是 AI 代理判斷「何時使用這個 Skill」的唯一依據。描述寫得不夠精確，代理就無法在正確時機觸發你的 Skill。

誤區 3：以為 Skills 只能用在 Claude

Agent Skills 已經是開放標準，不僅限於 Anthropic 生態系。在設計 Skill 時，應考慮跨平台相容性。

延伸思考

從「專用代理」到「通用代理 + Skills」的典範轉移

過去我們傾向為每個領域建構專用代理（研究代理、程式代理、財務代理），各自有窄範圍的 scaffolding。新的典範是：通用代理搭配簡單的底層工具（bash + filesystem），再透過 Skills 注入領域知識。

這個轉變對資安從業人員的啟示是：

  • 資安知識的標準化：滲透測試流程、合規檢查清單、事件回應 SOP 都可以封裝成 Skills
  • 團隊知識共享：資深人員的經驗可以透過 Skills 傳遞給整個團隊
  • 可審計性：Skill 是版本化的檔案，可以納入程式碼審查流程

思考題

  1. 在你的日常工作中，有哪些反覆向 AI 代理描述的流程，適合封裝成 Skill？
  2. Progressive Disclosure 如何幫助你在 token 有限的場景下，更有效率地使用 AI？
  3. Skills 的開放標準格式，對於企業的「AI 供應商鎖定」問題有什麼影響？
