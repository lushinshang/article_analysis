核心概念

兩類內建 Skills

在 github.com/anthropics/skills 倉庫中，Skills 分為兩類：

類別包含預設狀態
Document SkillsExcel、PowerPoint、Word、PDF永遠開啟（Claude.ai 內建）
Example Skillsskill-creator 等範例預設關閉（需手動啟用），skill-creator 除外

PowerPoint Skill 剖析

PowerPoint Skill 的 SKILL.md 內容非常豐富，包含：

  • YAML Frontmatter（name + description）
  • 操作概覽：建立、編輯、分析 PowerPoint 檔案
  • 底層腳本：讀取和寫入 .pptx 的 Python 程式碼
  • 設計原則：色彩、字型、排版指引
  • 色彩調色盤：當使用者未指定時的預設選擇

重要觀察

腳本（scripts）不是一開始就執行的——它們僅在必要時才被載入和執行。這再次印證了 Progressive Disclosure 的設計。

Skill Creator：元技能（Meta-Skill）

Skill Creator 是一個「用來建立 Skills 的 Skill」。它包含：

  • Skills 的最佳實踐知識
  • 明確的建立步驟流程
  • 三個 Python 腳本：init_skill.py（初始化）、package_skill.py（打包）、validate_skill.py（驗證）

三個 Skills + MCP 的完整工作流

本課展示了一個端到端的工作流：

  1. 修改行銷 Skill：用 skill-creator 將 CSV 資料來源改為 BigQuery（透過 MCP Server）
  2. 建立品牌 Skill：上傳品牌視覺規範和 logo，用 skill-creator 建立品牌指南 Skill
  3. 組合工作流：行銷分析 Skill（從 BigQuery 取資料）+ 品牌 Skill（套用風格）+ PowerPoint 內建 Skill（產生簡報）

學習路徑

本課三部分操作

Part 1：更新行銷 Skill 使用 BigQuery

  • 前提：需要設定 BigQuery MCP Server（或用 SQLite 替代）
  • 使用 Claude Desktop（因為 BigQuery MCP Server 是本地 MCP server）
  • 在 SKILL.md 中指定 MCP server 和 tool 名稱是最佳實踐

Part 2：建立品牌指南 Skill

  • 上傳品牌視覺文件 + logo 圖檔
  • 用 skill-creator 自動產生 SKILL.md + assets 資料夾

Part 3：組合完整工作流

  • 從 BigQuery 查詢資料 → 行銷分析 → 品牌風格套用 → 產生 PowerPoint 簡報
  • Claude 會自動讀取所有相關 Skill，逐步執行

教材資源

  • L3/prompts.md：三個部分的完整 Prompt
  • L3/updated_marketing_skill/：更新後的行銷 Skill
  • L3/brand_guidelines_files/：品牌視覺檔案
  • L3/brand_guidelines_skill/：產生的品牌 Skill
  • L3/output_report_example/：產生的 PowerPoint 範例

替代方案

不需要 BigQuery 也能完成練習。你可以用 SQLite + 對應的 MCP Server，或直接跳過 Part 1。

實務應用

MCP + Skills 的最佳實踐

在 SKILL.md 中使用 MCP Server 時，應明確指定：

## Data Access
Use the BigQuery MCP server (`mcp_bigquery`) to query data.
Tool: `mcp_bigquery_query`
Always specify a date range — avoid querying the entire table.

Skill Creator 的價值

  • 遵循最佳實踐自動產生 Skill 結構
  • 分析現有 Skills 的模式，確保新 Skill 與其互補
  • 自動建立必要的資料夾和檔案結構

資安應用：SOC 分析工作流

設想三個 Skills 的組合：(1) SIEM 查詢 Skill（透過 MCP 連接 Splunk/ELK），(2) 事件分類 Skill（定義威脅分類標準），(3) 報告 Skill（套用組織報告格式）。這三個 Skills 加上 MCP Server，就能建構自動化的 SOC Tier 1 分析流程。

常見誤區

誤區：Claude.ai 和 Claude Desktop 的 Skills 差異

Claude.ai 只支援遠端 MCP Server；Claude Desktop 支援本地 MCP Server。如果你的 MCP Server 是本地運行的（如 BigQuery MCP），必須使用 Claude Desktop。

誤區：完全依賴 Skill Creator

Skill Creator 很好用，但它產生的 Skill 品質取決於你提供的上下文品質。你仍然需要清楚描述需求、提供完整的參考文件。「Garbage in, garbage out」同樣適用。

延伸思考

Skills 的可組合性與微服務架構的相似性

Skills 的組合使用方式，與微服務架構有驚人的相似性：每個 Skill 負責單一職責，透過明確的介面（輸入/輸出格式）互相協作。模型扮演「協調器」（Orchestrator）的角色。

思考題

  1. Skill Creator 產生的 Skill 會自我參考嗎？（用 Skill Creator 來改進 Skill Creator 本身？）這引發了哪些有趣的問題？
  2. 在你的工作流中，哪些步驟適合用 MCP 取得資料，哪些適合用 Skill 定義流程？
  3. 如果你要設計 100+ 個 Skills 的命名系統，你會如何避免名稱衝突和觸發歧義？
