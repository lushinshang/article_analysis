核心概念回顧

講師 Elie Schoppik 在結語中提煉了四個關鍵訊息：

1. 從簡單開始，漸進擴展

建立 Skill 時，先從基本的 Markdown 指令開始，之後再依循 Progressive Disclosure 原則擴展。不要一開始就試圖建立完美的 Skill。

2. 觀察與迭代

監控你的代理在真實場景中如何使用你的 Skill，根據觀察結果迭代改進。Skill 的品質來自於持續的回饋迴圈。

3. Description 決定觸發時機

確保 description 包含足夠的細節，讓代理知道何時該使用這個 Skill。這是 Progressive Disclosure 第一層的關鍵。

4. 善用 Claude 的知識

Claude 本身就非常瞭解 Skills。你可以從簡單的對話開始建立 Skill，然後用 Skill Creator Skill 來對齊最佳實踐。

實務行動指南

第一步：建立你的第一個 Skill（30 分鐘）

  1. 選一個你每週都在做的重複性工作
  2. 把你平常會給 AI 的 prompt 整理成 SKILL.md
  3. 加入 YAML frontmatter（name + description）
  4. 上傳到 Claude.ai 測試

第二步：漸進式改善（1-2 小時）

  1. 觀察 Claude 如何使用你的 Skill
  2. 把「只有部分場景需要」的內容移到 references/
  3. 加入輸出範本到 assets/
  4. 用 Skill Creator 檢查最佳實踐

第三步：團隊推廣

  1. 分享 Skill 給團隊成員
  2. 收集回饋、迭代改進
  3. 建立 Skill 評估的單元測試
  4. 考慮在 Claude API 中自動化使用

快速起步建議

不要從零開始寫 SKILL.md。先把你的 prompt 直接貼給 Claude，說「請幫我把這個 prompt 轉換成一個 Agent Skill」。Claude 知道 Skills 的結構，會幫你產生初始版本。

最終注意事項

規格仍在演進中

Agent Skills 的開放標準仍在積極發展中。你可能會遇到不完全遵循當前規格的 Skills（包括 Anthropic 自己的一些早期 Skills）。保持關注規格更新。

延伸思考

Skills 生態系的未來

隨著越來越多平台採用 Agent Skills 開放標準，我們可以預見：

  • Skills Marketplace：類似 npm 的 Skills 生態系，開發者可以發佈和安裝 Skills
  • 企業 Skill 管理：組織級的 Skills 版本控管、權限管理和審計
  • Skills Composition Engine：自動化 Skills 組合和工作流編排

最終思考題

  1. 如果你只能為你的團隊建立三個 Skills，你會建立哪三個？為什麼？
  2. Skills 的開放標準化是否會改變 AI 工具的競爭格局？供應商的差異化將從何處體現？
  3. 在 Skills 越來越普及之後，「Prompt Engineering」這門技能會如何演化？
