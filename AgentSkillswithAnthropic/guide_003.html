核心概念

Skills 是開放標準

Agent Skills 不是 Anthropic 專屬技術。它是一個開放規格（Open Specification），已被多個平台採用：Codex、Gemini CLI、Claude Code、Open Code 等。這意味著你建立一次 Skill，就能在多個代理產品中使用。

從專用代理到通用代理的典範轉移

舊模式新模式
每個領域一個專用代理通用代理 + Skills 注入領域知識
各自有狹窄的 scaffolding簡單的 scaffolding：bash + filesystem
難以評估、理解和擴展更易評估、理解和擴展

通用代理需要的是上下文和領域專業知識，而 Skills 正是提供這些知識的機制。

Skills 的三大能力

能力類別說明範例
領域專業知識Claude 有通識能力，但不知道「你的公司怎麼做」品牌視覺規範、法律審查流程
可重複工作流在非確定性系統中建立可預測的輸出每週行銷分析、客戶電話準備
新能力代理原生不會做的事產生簡報、PDF 報表、建構 MCP 伺服器

Progressive Disclosure 深入解析

這是 Skills 架構中最核心的設計理念：

  1. 第一層：Skill 的名稱和描述永遠存在於 context window 中
  2. 第二層：當 Skill 被觸發時，載入 SKILL.md 主體內容
  3. 第三層：根據需要，載入額外的參考檔案和腳本

Context Window 是公共財

加入越多資料到 context window → 消耗越多 token → context 越快填滿 → context degradation（上下文退化）或不正確回應的機率越高。Progressive Disclosure 的目標就是在保護這個公共資源的前提下，提供必要的知識。

Skill 可以包含什麼？

  • Markdown 文件：指令、參考文件
  • 腳本：可被執行的 Python/Bash 程式碼
  • 資源：圖示、圖片、範本、CSV、schema

Skills 的可組合性（Composability）

多個 Skills 可以組合使用，建構複雜的工作流。例如：

  • 公司品牌 Skill：提供品牌視覺規範
  • PowerPoint Skill：產生簡報
  • BigQuery Skill：提供行銷資料 schema
  • 行銷分析 Skill：分析行銷資料

組合起來就是：從 BigQuery 取資料 → 行銷分析 → 品牌風格 → 產生簡報。

常見誤區

誤區：在 SKILL.md 中放入執行用的腳本程式碼

腳本應該放在獨立檔案中（例如 scripts/ 目錄），由 SKILL.md 引用。腳本的載入和執行是透過 bash/filesystem 工具完成的，不應直接嵌入指令文件中。

誤區：認為 Skills 能取代 MCP

Skills 提供的是「知識」（怎麼做），MCP 提供的是「存取」（取得資料）。兩者是互補關係，不是替代關係。下一課（guide_007）會深入討論這個區分。

延伸思考

非確定性系統中的可預測性

LLM 本質上是非確定性的——相同的輸入不一定得到相同的輸出。Skills 透過明確的步驟和格式要求，在非確定性系統中創造可預測的工作流。這與軟體工程中「透過約束減少變異」的原則一致。

思考題

  1. Progressive Disclosure 有三層載入機制。在你的使用場景中，哪些資訊應該放在第一層（永遠載入）、第二層（觸發時載入）、第三層（視需要載入）？
  2. Skills 的開放標準化，對「AI 代理的可替換性」有什麼商業意義？
  3. 在非確定性系統中建立可預測性，除了 Skills 之外還有哪些策略？
