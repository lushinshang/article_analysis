核心概念

不同環境的 Skills 基礎設施

Skills 在每個環境中的格式不變，但底層基礎設施有差異：

環境Code ExecutionFile System配置方式
Claude.ai / Desktop內建（自動啟用）內建自動配置
Claude Code直接存取本機直接存取本機自動配置
Claude API需手動啟用 Code Execution Tool需使用 Files API手動配置

關鍵差異

在 Claude.ai 建立的 Skills，不會自動同步到 Claude API 或 Claude Code。每個環境各自管理自己的 Skills。

Code Execution Tool

Code Execution Tool 提供一個沙盒容器（sandbox container），讓 Claude 能：

  • 執行 Bash/Shell 命令
  • 建立、編輯、檢視檔案
  • 執行 Python 程式碼

限制條件：

  • 有 RAM、磁碟空間、CPU 限制
  • API 版本無網路連線（Claude.ai/Desktop 版本有）
  • 僅有預裝的程式庫

Files API

Files API 用來上傳和下載檔案到/從沙盒容器：

  1. 上傳：將 Skill 目錄和輸入檔案上傳到容器
  2. 處理：Claude 在容器中讀取 Skill、執行分析、產生輸出
  3. 下載：取得產生的檔案（報告、文件等）

API 中使用 Skills 的流程

# 1. 上傳 Skill 目錄
skill = client.skills.create(files_from_dir("custom_skills/my-skill"))

# 2. 上傳輸入檔案
file = client.files.create(open("input.csv", "rb"))

# 3. 發送請求（需要三個 beta headers）
response = client.messages.create(
    model="claude-sonnet-4-5-20250514",
    betas=["skills", "code-execution", "files-api"],
    container={"skills": [{"id": skill.id, "version": "latest"}]},
    tools=[{"type": "code_execution"}],
    messages=[{"role": "user", "content": [...]}]
)

# 4. 下載產生的檔案
output = client.files.download(file_id)

實務應用

Beta Headers 的重要性

使用 API 搭配 Skills 時，需要傳入三個 beta headers：

Header用途
skills啟用 Skills 功能
code-execution啟用沙盒容器執行程式碼
files-api啟用檔案上傳/下載

自訂 Skill + 內建 Skill 的混用

在 container 參數中，可以同時列入：

  • 自訂 Skill（用 skill ID）
  • 內建 Skill（用 Anthropic 提供的識別碼，例如 docx）

兩者遵循相同的 Progressive Disclosure 機制。

自動化合規報告

透過 API 程式化使用 Skills，你可以將報告生成整合到 CI/CD pipeline 中。例如：每次弱點掃描完成後，自動觸發 API 呼叫，使用「弱點分析 Skill + Word Skill」產生合規報告。

常見誤區

誤區：API 沙盒有完整網路存取

API 的 Code Execution Tool 沙盒沒有網路連線。這與 Claude.ai/Desktop 不同。如果你的 Skill 需要下載套件或存取外部 API，必須在上傳前預先準備好所有依賴。

誤區：Skills 跨環境自動同步

在 Claude.ai 上傳的 Skill 不會出現在 API 或 Claude Code 中。每個環境都需要獨立管理自己的 Skills。

誤區：忘記指定 beta headers

缺少任何一個 beta header 都會導致 Skills 無法正常運作。最常見的錯誤是只加了 skills 但忘了 code-execution。

延伸思考

Skills 的版本管理

API 支援 Skill 的多版本管理。你可以指定特定版本或使用 latest。在生產環境中，建議固定版本號，避免 Skill 更新導致非預期行為。這與軟體的依賴管理（如 npm lock file）是同樣的思維。

思考題

  1. API 沙盒沒有網路連線，這對 Skill 設計有什麼限制？你會如何設計一個需要外部資料的 Skill 來繞過這個限制？
  2. 在 CI/CD pipeline 中使用 Skills，你會如何處理 API 費用控管和失敗重試？
  3. 自訂 Skill 和內建 Skill 混用時，如果兩者的輸出格式衝突，模型會如何處理？你能設計一個測試來驗證嗎？
