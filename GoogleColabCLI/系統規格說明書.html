Google Colab CLI 語音下載、字幕優先偵測、切割與 Whisper 一鍵轉錄自動化套件規格書

1. 專案背景與痛點

隨著長時間會議、課堂或聽證會影音檔案的增加，語音轉文字（STT）已成為日常工作流中的核心需求。OpenAI 開源的 Whisper 大模型（如 large-v3）具備極高的中文辨識率，但其對硬體運算（特別是 GPU 記憶體）有極高要求，一般使用者的本機電腦通常無法順暢運作。

本專案基於 google-colab-cli 的雲端運作基礎，設計出一套本地與雲端 VM 無縫協同的一鍵式工作流。使用者不需具備 Git 使用背景與程式開發經驗，只要執行一個簡單的指令，即可藉由 Google 免費/付費的雲端 GPU 算力完成高精度轉錄，並自動打包回傳結果。

2. 使用者痛點與對應解決方案 (Feature Mapping)
使用者痛點 (Pain Point) 對應解決方案 (Solution)
GPU 配額不足無法啟動
免費版 Google 帳號在熱門時段常搶不到 T4 GPU 算力，導致 VM 建立失敗而卡死。		 GPU/CPU 自動降級機制
建立 GPU 會話若失敗，程式會自動以 CPU 重新部署，避免任務直接中斷。
長音訊檔案大、傳輸慢、易爆雲端容量
動輒幾百 MB 甚至上 GB 的原始音訊，如果轉無損 WAV 傳輸耗時，且易爆 Colab 根目錄的空間。		 雲端暫存大檔清理與可選切割
支援在本機引導音訊「切割時間」。雲端只下載原檔並轉 WAV，切出欲轉錄之小音訊後，即時刪除原始巨型 WAV，既省本機傳輸流量也防雲端洩漏。
Whisper 載入大模型重複超時
用 Shell 迴圈每次調用 Whisper 指令會重複下載與載入 3GB 大模型，造成嚴重的時間浪費。		 批次處理與模型載入優化
以 Python 腳本在雲端一次性載入 Whisper 模型，直接將多個 WAV 音訊作為 List 批次送入，只載入模型一次。
忘記關機導致點數/額度浪費
轉錄動輒數十分鐘，使用者離開電腦若未手動關機，VM 會一直扣點直到閒置超時自動中斷。		 自動防忘關機安全網
無論轉錄任務成功、失敗、甚至是中斷退出，本機腳本一定會在結束前向雲端發送 colab stop 關機指令，絕不浪費多餘計費。
不懂 Git 與虛擬環境設定的繁瑣步驟
使用者不懂 uv venv, source .venv/bin/activate 等指令，經常因為沒在虛擬環境執行而出錯。		 一鍵整合入口 run.sh
單一入口 ./run.sh，自動建立虛擬環境與執行 uv sync 保持程式碼最新，不需手動啟用虛擬環境。
YouTube 影片明明已有字幕，卻仍要花時間下載音訊並用 GPU 轉錄
許多 YouTube 影片本身已附帶官方或自動產生的字幕，重新下載音訊並跑 Whisper 既浪費時間也浪費雲端算力。		 YouTube 字幕優先偵測
未選擇切割時，優先檢查並直接下載既有字幕（同時輸出 .srt 與 .txt），完全略過音訊下載與轉錄。
手邊已有錄音檔，卻要先上傳到 Google Drive 取得分享連結才能處理
使用者本機已有 .m4a/.mp3/.mp4/.wav 錄音檔，若仍須手動上傳雲端硬碟並設定分享權限才能餵給工具，流程繁瑣且耗時。		 本地音訊直傳上傳 (sound/ 目錄)
將檔案放入本機 sound/ 目錄並執行選單選項 2，透過 colab upload 直接傳送至雲端 VM 並就地轉換為 WAV，免去手動上傳雲端硬碟與產生分享連結的步驟。
3. 核心功能規格需求 (Functional Requirements)
  • FR1. 一鍵環境管理器 (run.sh)： 本機執行的 Shell 入口，必須自動檢測 .venv，若無則建立，並運行 uv sync 自動拉取最新開發分支與 CLI 軟體包，免除使用者手動同步。執行前會以 colab sessions 偵測雲端是否存在保留中的會話 (dl-session)，據此動態決定選單項目與編號（第二階段轉錄選項僅在偵測到保留會話時顯示）。
  • FR1.5. 本地音訊直傳與轉檔 (run1_local.sh / process_audio.py --local)： 本機執行的 Shell 子流程，掃描 sound/ 目錄下的 .m4a/.mp3/.mp4/.wav 檔案供使用者選擇全部或指定編號，透過 colab upload 將所選檔案傳送至雲端 VM 的 /content/ 目錄，再以 process_audio.py --local <檔名...> 模式呼叫既有的 convert_to_wav() 轉換為 16kHz、16-bit Mono WAV，產出清單寫入 output_files.txt，與第一階段共用後續的會話保留／本地下載／自動關機流程。
  • FR2. 音訊智能下載與轉換 (process_audio.py)： 雲端執行的 Python 腳本，必須支援普通 HTTP URL、Google Drive URL (自動抽取 File ID) 及 YouTube 網址；自動安裝 ffmpeg 及 yt-dlp 套件，並轉換音訊為 16kHz、16-bit Mono (單聲道) WAV。
  • FR2.5. YouTube 字幕優先偵測與下載 (process_audio.py)： 當輸入為 YouTube 網址且使用者「未選擇切割」時，優先以 yt-dlp 檢查影片是否具備字幕，語言優先序為 zh-TW > zh-Hans > zh-Hant > zh > en（含手動字幕與自動字幕）。若有，直接下載字幕並同時輸出 .srt (含時間碼) 與 .txt (純文字) 兩種格式，完全略過音訊下載與 Whisper 轉錄；若無可用字幕或使用者已選擇切割，則一律走音訊下載流程。
  • FR3. 多區段音訊切割與殘留清理 (process_audio.py)： 支援使用者設定多個時間區段（支援 24小時制數字如 1030 或標準時間格式 10:30:00），將基準時間與切割時間做相差毫秒計算，切出子音訊 WAV 檔案後，必須在雲端磁碟中刪除原始大型 WAV 檔。時間參數採「時鐘時間」語意：例如基準開始時間設為 0000，欲擷取前 7 分鐘則結束時間應輸入 0007（00:07）而非 0700；若結束時間換算後超過音訊實際長度，將自動裁切至音訊結尾（等同未切割，轉錄整段原始音訊）。
  • FR4. 雲端 Whisper 智能轉錄與字幕分流 (transcribe_audio.py)： 優先讀取第一階段產出的 output_files.txt 清單，依副檔名分流：.wav 才載入 Whisper 模型進行轉錄，支援 GPU/CPU 智能適配（GPU 模式使用 large-v3，CPU 模式自動降級為 medium 避免計算超時），轉錄結果同時輸出 .txt (純文字) 與 .srt (含時間碼) 兩種格式，並透過 OpenCC (s2twp) 統一轉換為繁體中文（台灣慣用語）；.srt/.txt（字幕直出結果）則直接收錄至輸出目錄，不會載入 Whisper 模型。
  • FR5. 動態轉錄超時安全閥 (run2.sh)： 在第二階段啟動時，本機須先發送一個 0.1 秒的探測命令取得雲端所有 *.wav 的總時間秒數，並套用公式 Timeout = (總秒數 / 2) + 300 (下限 10 分鐘) 動態設定轉錄的 timeout；若偵測到總秒數為 0（純字幕模式，無 WAV），則改用 120 秒的固定短超時。
1. 系統架構與部署模式

本系統基於本地與雲端 VM 的「分散式協同」架構。本地端透過 google-colab-cli 建立 Jupyter 連線，並以管道注入的方式直接發送 Python 代碼給雲端 VM 執行，因此本地端無需配置任何 Python 依賴（只需安裝 uv），所有的音訊處理與模型推論皆在 Google 雲端完成。

離線安裝包（位於 installation/ 目錄）與 CLI 原始碼目錄完全解耦。使用者可直接複製 installation/ 目錄到電腦的任意位置（如桌面），將其作為自包含的應用工具包使用。

2. 外在軟體與系統元件依賴
元件名稱 部署位置 功用說明
uv (v0.11+) 本機電腦 高效 Python 虛擬環境與依賴套件管理工具。
google-colab-cli (v0.5.9+) 本地虛擬環境 透過 Jupyter 與 Colab Control Plane 進行認證、VM 開關與代碼傳輸。
ffmpeg 雲端 VM 系統級音訊解碼、編碼與分割元件 (自動於 process_audio.py 中檢測並安裝)。
openai-whisper (GPU/CPU) 雲端 VM 語音轉文字推論引擎 (自動於 transcribe_audio.py 中安裝與加載)。
3. 核心 Bug 修復規格明細 (Defect Fix Specifications)

為了確保整個下載與轉錄流程穩定，專案內部對原生 CLI 進行了以下修改：

A. 目錄下載缺陷修復

  • 模組名稱：colab_cli.commands.files.download
  • 問題描述：原本 colab download -s session "remote_file" . 時，若本地目的地為目錄 .，Contents API 會拋出 IsADirectoryError 錯誤。
  • 修復規格：引入 os.path.isdir(local_path) 檢測。若為目錄，自動將遠端檔案的 os.path.basename 結合，重新拼接為具體檔案路徑，確保正常下載。

B. 會話狀態回傳值修復

  • 模組名稱：colab_cli.commands.session.status
  • 問題描述：當指定的會話（例如 dl-session）在伺服器端不存在時，colab status -s dl-session 雖印出 Session not found，但 Exit Code 卻回傳 0。這會導致 Shell 腳本的 $? 誤判會話依然活躍。
  • 修復規格：在找不到會話的分支中加入 raise typer.Exit(1)，確保向 Shell 回傳非零的錯誤碼，使得會話檢測腳本能正常攔截。
4. 系統限制與非功能性規格
  • 雲端最大空閒限制 (Idle Timeout)：Colab 虛擬機在閒置（無程式碼執行）約 30 ~ 90 分鐘後會被自動回收。因此第一階段切割完且保留會話後，應盡快執行第二階段。
  • 檔案大小限制：支援高達 2GB 的原始影音下載。雲端下載過程超時限制為 600 秒 (10 分鐘)。
  • 轉錄超時保護：動態評估秒數大於 30 分鐘時，將自動放寬 colab exec --timeout 限制，最高可達 Colab 平台所容許的單次連線最大上限。
  • 雲端零殘留 (No Cloud Residue)：全程不掛載、不寫入使用者的 Google Drive；所有處理皆在 Colab VM 的暫存磁碟進行，colab stop 後該 VM 連同其上所有檔案與執行 log 一併銷毀，僅本機端會保留 ./whisper_output/ 下載結果。
